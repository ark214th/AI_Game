## 1. コンセプト

**「覚え方を身につける」ことが、そのまま攻略法になるローグライト。**

プレイヤーは夢の迷宮に潜る蒐集家（しゅうしゅうか）。依頼人から品物のリストを受け取るが、リストは迷宮に持ち込めない。
そこで、自分だけの「記憶の館」の部屋に品物を置いて覚え、暗闇の迷宮をランタンの一瞬の光を頼りに進み、祭壇で正しい品を順番どおりに選び取る。

- 想定プレイヤー：まずは作者本人（大人）。面白ければ難易度を調整して子ども（小学生）向けにも展開する
- 1ラン：8〜12分。1日1〜3ランを想定
- プラットフォーム：Web（PC ブラウザ＋ iPad Safari）。タッチとマウスの両方に対応

## 2. 制作意図（研究上の根拠）

このゲームは、認知トレーニング研究で**比較的効果が確認されている要素だけ**を選び、それをゲームの中心的な仕組みに据えている。
「退屈な訓練課題にゲームの見た目をかぶせたもの」（いわゆるチョコがけブロッコリー）にしないことが最大の目的。

| 研究上の知見 | ゲームでの実装 |
|---|---|
| 記憶術（場所法）は、6週間の訓練で単語リストの再生数を2倍以上に伸ばし、4か月後も効果が続いた（Dresler et al. 2017）。同じ研究で、ワーキングメモリ訓練の群には効果がなかった | **記憶の館**：品物を館の決まった道順に沿って置き、道順をたどって思い出す。これが攻略の本体 |
| 処理速度訓練（中心の対象を見分けながら、周辺に一瞬出る対象の位置を答える課題）は、ブースター訓練と組み合わせると、高齢者の認知症診断率を20年にわたり下げた（ACTIVE 研究、2026年報告） | **閃光（せんこう）**：暗い部屋をランタンが一瞬だけ照らす。中心の紋章と周辺の宝の位置を読み取る |
| アクションゲームは、他のゲームと比べて注意・知覚・空間認知を向上させる（Bediou et al. 2018, g≈0.34）。ただし記憶への効果はない | 閃光フェーズにスピード感、予測しにくさ、注意の分割を入れる |
| ACTIVE 研究の処理速度訓練は、成績に応じて難しくなる設計だった | すべての課題に**適応難易度**（階段法）を入れる |
| 同じ課題を繰り返すと、「その課題が上手くなるだけ」で終わりやすい | 刺激・部屋・品物・演出にバリエーションを持たせる |
| 時間を空けて思い出すこと（分散学習・想起練習）で記憶は定着する | **預かり依頼**：品物を館に置いたまま数日後に返却を求められる |
| N バック課題の効果は、主に似た課題への近転移に限られる | N バック的な要素は補助的な仕組みにとどめる（第5章7節） |

**効能はうたわない。** 言ってよいのは「場所法という記憶術を練習できる」まで。「頭が良くなる」「認知症予防」などは書かない（第12章）。

## 3. 設計の柱

作者の設計方針に沿って、次の3つを柱とする。優先度は上から順。

1. **単体で面白いこと**：訓練効果を知らない人が遊んでも面白い。訓練の要素は面白さの源泉であって、義務ではない。
2. **周回による成長と、リスクとリターン**：館が広がる（覚えられる量が増える）ことが、プレイヤーの成長と一致する。欲張るほど報酬は大きいが、覚える量も増える。
3. **見た目とエフェクトだけで結果が伝わること**：数値を読まなくても、成功と失敗が演出で分かる。

## 5. 各フェーズの詳細

### 5.1 依頼選択

- 掲示板に依頼書が3〜4枚並ぶ。各依頼は3〜6品程度のリストで、報酬と難度（品数、制約）が書かれている
- プレイヤーは**何件受けるか**を選ぶ。受けた依頼の品物はすべて1回の潜行で集める＝その分だけ覚える量が増える
- 特殊な依頼の例：
  - **順番指定**：「3番目の品は何か」と途中で聞かれる（道順の途中から思い出す練習になる）
  - **預かり依頼**：今回は品物を館に置くだけ。後日、依頼人が取りに来る（5.6節）
- 意図：覚える量（スパン）をプレイヤー自身が選ぶことで、難易度調整がそのまま**リスクとリターンの判断**になる

### 5.2 記憶の館への収納（場所法フェーズ）

この作品の核。ここが面白くなければ作品は成立しない。

**館の構造**
- 館は複数の部屋からなり、**決まった道順**（玄関→廊下→書斎→…）で一周できる
- 各部屋に**置き場（ロキ）**が3〜5個ある。置き場は家具（暖炉、柱時計、本棚、浴槽など）に対応する
- 道順と置き場の順番は固定。この固定された順序が、場所法の「順番どおりに思い出せる」性質を生む

**収納の操作**
1. 依頼書の品物が1つずつ手元に出る
2. プレイヤーは館の中を道順に沿って進み、品物を置き場にドラッグして置く
3. 置いた瞬間、**品物と家具が奇妙な相互作用をするアニメーション**が再生される（例：魚を暖炉に置く→魚が炎の中でタップダンスを踊る）
4. 収納が終わったら依頼書は燃えて消える（演出で「もうリストは見られない」ことを示す）

**相互作用アニメーションの設計**
- 奇妙で印象的なイメージほど記憶に残る、という記憶術の原理を、プレイヤーが意識しなくても体験できるようにする
- 組み合わせの数が爆発しないよう、データ駆動で生成する：
  - 品物には「性質タグ」（例：`fish`：跳ねる、濡れる、光る）
  - 家具には「反応タグ」（例：`fireplace`：燃やす、煙を出す、吸い込む）
  - タグの組み合わせから、汎用のモーション（跳ねる、回転、巨大化、色変化、パーティクル）を選んで合成する
- 初期は汎用モーション10種程度で十分。手作りの特別な組み合わせは後から少しずつ足す

**制限時間**
- 収納フェーズには緩めの制限時間（砂時計）がある。時間を残して終えると、潜行時のランタン油にボーナス
- 意図：じっくり覚えるか、速く覚えて報酬を得るか、というリスクとリターンを作る。ただし初心者モードでは時間制限なし

**館の拡張と模様替え（5.5節と連動）**
- 置き場の家具はプレイヤーが選んで配置する。自分で作った空間ほど、記憶の手がかりとして強くなる
- 部屋が増える＝置き場が増える＝一度に覚えられる量が増える。**館の成長とプレイヤーの記憶力の成長が一致する**のがこの作品の要

### 5.3 潜行：閃光フェーズ（処理速度の訓練）

迷宮は真っ暗。部屋に入るたびに、ランタンが**一瞬だけ**部屋を照らす。

**1回の閃光の流れ**
1. 画面中央に注視点を表示（0.5〜1秒）
2. **閃光**：中央に紋章（2〜4種類のどれか）、周辺（8方向のどれか）に宝箱または祭壇が同時に表示される
3. **マスク**：すぐに光がノイズ（煙や残像）で覆われる。これにより網膜の残像で答えられないようにする（技術的な注意は第10章）
4. プレイヤーの回答：
   - 中央の紋章を選ぶ（紋章によって進むべき扉が決まる）
   - 周辺の対象があった方向をタップする（その方向に進むと宝や祭壇がある）

**難度の段階**（適応難易度で自動的に上がる）
- 段階1：中央の紋章の識別のみ
- 段階2：中央の紋章＋周辺の位置（注意の分割）
- 段階3：段階2＋周辺に妨害物（コウモリ、偽の宝箱など）
- 表示時間は段階とは別に、成績に応じて短くなる（第6章）

**結果の演出**
- 両方正解：扉が開き、宝の位置に光の筋が伸びる。コンボ演出
- 片方不正解：罠が作動し、ランタン油が減る
- 意図：処理速度の課題を、「暗闇を一瞬の光で見抜く」という体験に置き換える。ステージごとに見た目を変える（嵐＝画面にノイズ、霧＝コントラスト低下、地底湖＝反射した偽像）ことで、刺激にバリエーションを持たせる

### 5.4 潜行：祭壇フェーズ（遅延想起）

閃光の間に、ときどき祭壇の部屋がある。

- 祭壇には3〜5個の候補が並ぶ。プレイヤーは「次に集めるべき品」を選ぶ
- 候補には正解に加えて、依頼にない品物（ダミー）と、依頼にはあるが順番の違う品物が混ざる
- 難度が上がると、ダミーが正解と同じカテゴリ・似た見た目になる
- **順番指定の依頼**では「3番目の品は？」と聞かれる
- 閃光の部屋を挟むことで、自然と遅延想起になる。潜行中に館を見返すことはできない

**リスクとリターン**
- 正解：品物を回収。演出で依頼書の該当行が光る
- 不正解：品物が**ミミック**に変わって襲ってくる（ランタン油を失う、または呪いを受ける）
- **記憶の灯（ともしび）**：消費アイテム。使うと館の1部屋を2秒だけ覗ける。ただし報酬が減る。「どうしても思い出せない」ときの救済と、使わずに進む緊張感を両立させる

### 5.5 帰還・精算とメタ進行

- ランタン油が尽きるか、全品回収すると帰還
- 精算画面：回収した品、依頼の達成度、ボーナスを演出付きで表示
- 報酬で得られるもの：
  - **館の拡張**：新しい部屋（置き場が増える）
  - **家具**：置き場の見た目を変える。組み合わせで新しい相互作用アニメーションが解放される
  - **ランタンの強化**：油の最大量など。ただし**閃光の表示時間を延ばす強化は作らない**（訓練の核を損なうため）
- 意図：周回するほど館が広く豪華になり、それが「覚えられる量が増えた」ことの目に見える証拠になる

### 5.6 預かり依頼（日をまたいだ想起）

- 依頼人から「この品を預かってほしい」と頼まれ、館の置き場に置く
- **後日**（1日後、3日後、7日後など）依頼人が現れ、「何を、どこに預けたか」を聞く
- 間隔が長いほど報酬が大きい
- 預かり品は置き場を占有する → 通常の依頼で使える置き場が減る、という**容量のジレンマ**が生まれる
- 意図：分散学習と想起練習。実時間（端末の日付）を使う
- 注意：何日も遊ばなくても罰は与えない。依頼人は「待っていた」と言うだけで、報酬が少し下がる程度にとどめる

### 5.7 補助要素：反響（N バック的な仕組み）

効果は限定的なので、主役にはしない。潜行のアクセントとして使う。

- **反響の部屋**：部屋に入るたびに鐘の音と色が1つずつ出る。「2部屋前と同じなら、盾を構える（タップ）」と、亡霊の攻撃を防げる
- 深い階層でのみ登場するスパイス。無効化する設定も可能にしておく

## 6. 適応難易度システム

**目的**：常に「少し難しいが、だいたい成功する」状態を保つ。成功率の目標は約80%。

**方式**：課題の要素ごとに独立した階段法（staircase）を持つ。
- 3回連続正解で1段階難しく、1回不正解で1段階易しくする（3-down 1-up。成功率約79%に収束する）
- 表示時間は対数スケールで変える（例：500ms → 400 → 320 → … 下限は1フレーム）

| パラメータ | 対象フェーズ | 初期値（大人） | 変化の方向 |
|---|---|---|---|
| 閃光の表示時間 | 閃光 | 500ms | 短くなる |
| 周辺の妨害物の数 | 閃光 | 0 | 増える |
| 周辺対象の距離（離心率） | 閃光 | 近い | 遠くなる |
| 依頼の品数（推奨値） | 依頼・収納 | 5 | 増える（プレイヤーが選ぶ上限の目安） |
| 祭壇のダミーの類似度 | 祭壇 | 低い | 高くなる |

- 階段の状態はセーブデータに保存し、セッションをまたいで引き継ぐ
- **数値はプレイヤーに見せない**。代わりにランタンの炎の大きさや部屋の暗さといった演出で、難しくなったことが伝わるようにする

## 7. 演出方針

「見た目とエフェクトだけで成功・失敗が伝わる」を徹底する。

- **成功**：光が広がる、金色のパーティクル、依頼書の行が光る、コンボで音程が上がる
- **失敗**：画面が一瞬暗くなる、ランタンの炎が揺らぐ、ミミックの歯が鳴る
- 閃光の瞬間は演出を最小限にし、刺激の読み取りを邪魔しない。**演出は閃光の前後に置く**
- 収納時の相互作用アニメーションは、この作品で最も手をかける演出。「変で、少し笑える」を目指す
- 美術の方向性の候補：ローポリ3Dの館（three.js）＋暗闇とランタン光のコントラスト。子ども向けにも怖くなりすぎないトーン

## 8. 子ども向けの調整（将来）

大人用で面白さを確認してから着手する。同じコードで、難易度プロファイルを切り替えられるようにしておく。

| 項目 | 大人 | 子ども |
|---|---|---|
| 品数の初期値 | 5 | 3 |
| 閃光の初期表示時間 | 500ms | 800ms |
| 収納の制限時間 | あり | なし |
| 祭壇のダミー | 似た品あり | 見た目が大きく違う品のみ |
| 反響の部屋 | 深層で登場 | 登場しない |
| 失敗の表現 | ミミックが襲う | ミミックがくすぐってくる程度 |

- 品物は絵にしやすい具体的な名詞（動物、食べ物、道具）にする。場所法は、イメージしやすいものほど効果が高い
- 子どもは場所法を知らないので、最初の数回は館の案内役が「変な置き方をすると覚えやすいよ」と自然に教える
- 拡張案：依頼の品物を漢字や英単語にすると、学習内容の暗記にも使える（ただし絵にしにくい語は場所法と相性が悪いので注意）

## 9. 計測モード（任意）

訓練で上手くなったのが「このゲームだけ」なのか、「ゲームの外でも」なのかを自分で確かめるための機能。ゲーム本編とは分ける。

- **単語リストの自由再生**：ゲームに出てこない単語を20語表示 → 数分後に思い出せる数を記録
- **周辺視野テスト**：ゲームとは違う刺激（記号、色）で、閃光と同じ形式のテストを行う
- 週1回程度を推奨。結果は折れ線グラフで表示し、JSON でエクスポートできるようにする
- 意図：訓練課題そのものの成績だけで効果を判断しない（研究で繰り返し指摘されている落とし穴）

## 10. 技術方針

### 10.1 スタック（案）
- TypeScript ＋ Vite ＋ three.js
- PWA 化して iPad のホーム画面から起動できるようにする
- サーバーなし。セーブは IndexedDB（または localStorage）。JSON でのエクスポートとインポートに対応

### 10.2 アーキテクチャ
- **ゲームロジックと描画を分離する**。ロジック（依頼生成、判定、階段法、セーブ）は純粋な TypeScript で書き、単体テストできるようにする
- 乱数は seed を指定できるものを使う（再現性、デバッグ、テストのため）
- コンテンツはデータ駆動：品物、家具、タグ、相互作用モーション、依頼テンプレートは JSON で定義する
- 難易度プロファイル（大人、子ども）も設定データとして持つ

```
src/
  core/        # ロジック（描画に依存しない）
    run/       # ラン進行、依頼、判定
    palace/    # 館の構造、置き場、道順
    adaptive/  # 階段法
    save/
  render/      # three.js 描画、演出
  ui/          # 入力、HUD
  content/     # JSON（items, furniture, tags, requests）
  config/      # 定数、難易度プロファイル
  measure/     # 計測モード
```

### 10.3 閃光の表示時間に関する注意（重要）
閃光は数十ミリ秒の精度が必要なので、次を守ること。

- 表示時間は `setTimeout` ではなく **`requestAnimationFrame` のフレーム単位**で制御する。表示時間は「何フレーム表示するか」に変換する（60Hz なら約16.7ms 単位。iPad の ProMotion は最大120Hz）
- 起動時に端末の実際のリフレッシュレートを計測し、フレーム時間を決める
- 実際に表示されたフレームのタイムスタンプを記録し、ログに残す（狙った時間と実際の時間のずれを確認するため）
- **刺激の直後に必ずマスクを表示する**。マスクがないと残像で答えられてしまい、訓練にならない
- 閃光の最中は重い処理（テクスチャ読み込み、GC を誘発する大量の生成）をしない。閃光の直前にアセットを読み込み終えておく

### 10.4 入力
- タッチとマウスの両方に対応する。閃光の回答は、方向ボタン（8方向）と紋章ボタンで行う
- 反応時間を記録するが、判定には使わない（正確さを優先する。速さの評価は表示時間の短縮で行う）

各段階で「面白いか」を確認してから次に進む。面白くなければ、次に進まずにその段階で直す。

## 12. 判断基準（迷ったときに）

**優先順位**
1. 面白さ
2. 訓練の核（場所法の構造、閃光の表示時間とマスク、適応難易度）を損なわないこと
3. 実装の単純さ

**やらないこと**
- 潜行中に依頼リストや館を自由に見返せる機能、メモ機能（「記憶の灯」による制限つきの覗き見は例外）
- 閃光の表示時間を延ばすアイテムや強化（難しさは階段法でのみ調整する）
- 遊ばなかった日に罰を与える仕組み（ログインボーナスの取り逃しで損をする、など）
- 「脳年齢」のような、効果を連想させる数値表示
- 「頭が良くなる」「記憶力が上がる」「認知症予防」といった効能の表記。言ってよいのは「場所法という記憶術を練習できる」まで

**迷ったら入れてよいもの**
- 刺激や見た目のバリエーション（転移のためにも、飽き防止のためにも有効）
- 成功と失敗の演出の強化
