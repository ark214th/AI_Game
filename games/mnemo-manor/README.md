# 記憶の館（仮題：Mnemo Manor）

場所法（記憶術）と、一瞬の光で部屋を見抜く「閃光」を軸にしたローグライト。企画と制作意図は [DESIGN.md](DESIGN.md)。

**いまの段階：M0（閃光の単体プロトタイプ）**。完成するまでトップの `index.html` からはリンクしない。確認は直接リンク（`games/mnemo-manor/`）で行う。

## M0 でできること

- 暗闇 → 注視点（0.5〜1秒、毎回ランダム）→ 閃光 → パターンマスク → 回答、の1回を「部屋」として20部屋進む「試し潜り」
- 段階1：中央の紋章（太陽・月・星・王冠）を答える
- 段階2：＋周辺8方向のどこかに光る宝箱の方向も答える
- 段階3：＋コウモリ・偽の宝箱（ミミック）がまぎれる
- 部屋の見た目：石の回廊／霧の間（コントラスト低下）／嵐の塔（ノイズと雨）／地底湖（段階2以降。反射した偽像）
- ランタン油：失敗で1減り、尽きたら帰還。5連続成功で1戻る
- 数値は見せない。難しくなるほどランタンの炎が小さくなり、注視点の部屋が暗くなる。帰還画面で「潜る前」と「いま」の炎を並べる

## 適応難易度（`core/adaptive/`, `core/flash/flash.mjs`）

- 3-down 1-up の階段法を、要素ごとに独立して持つ：表示時間／周辺対象の距離／妨害物の数
- 1回ごとに動かす階段を順番に回す（段階1：表示時間だけ、段階2：表示時間と距離を交互、段階3：表示時間・距離・表示時間・妨害物）
- 表示時間は 500ms から 0.8 倍ずつ（対数スケール）。下限はその端末の1フレーム
- 段階は、直近12回の成功率で上げ下げする（10回以上やって83%以上で上がる。12回で50%以下なら下がる）。上がったときは表示時間を2段階やさしく戻す
- 階段の状態はプロフィール（おとな・こども）ごとに保存し、次の潜行に引き継ぐ

## 表示時間の精度（DESIGN.md 10.3）

- `setTimeout` は使わず、`requestAnimationFrame` のフレーム数で表示する。潜るたびに実際のリフレッシュレートを測り直す（60Hz／120Hz など）
- 閃光とマスクの絵は注視点のあいだに別の canvas に描いておき、本番のフレームでは `drawImage` 1回だけ
- 1回ごとに、狙った時間・フレーム数・実測の時間（閃光を描いたフレームからマスクを描いたフレームまで）・フレーム落ちの有無を記録する。フレーム落ちした回は階段を動かさない
- 閃光の途中で画面が隠れたり、大きさが変わったりしたら、その回は採点せずにやり直す
- 閃光の最中は効果音を鳴らさない（光るタイミングの手がかりになるため）

## 操作

- タッチ・マウス：中央の2×2が紋章、まわりの8つが方向。段階2以降は両方選ぶと判定
- キーボード：`1`〜`4` 紋章、`Q W E / A D / Z X C`（またはテンキー、矢印キー）で方向。タイトル・帰還画面で `Space` / `Enter` で潜る。`Esc` でやめる

## テストプレイ用

- URL の末尾に `?debug` を付けると、左下にリフレッシュレート、各階段の段階と表示時間、直前の回の「狙った時間／実測／フレーム落ち／反応時間」が出る。段階1〜3の切りかえと、ログの JSON 保存ボタンもある
- `?seed=123` で乱数を固定できる
- 「せってい」から記録の書き出し・読みこみ（JSON）ができる

## 構成

ビルド不要。フォルダをそのまま HTTP で配信すれば動く。外部の CDN・画像・音声は使わない。
DESIGN.md 10.1 の案は TypeScript＋Vite だが、このリポジトリはどのゲームもビルドなしで GitHub Pages に置いているので、ES モジュール（`.mjs`）で書き、フォルダ構成とロジック／描画の分離は 10.2 に合わせている。

```
config/tuning.mjs          調整用の数値（プロフィール、階段法、段階の上げ下げ）
core/rng.mjs               seed 付き乱数
core/adaptive/staircase.mjs 階段法
core/flash/flash.mjs       閃光の1回の生成・判定・難易度の更新
core/flash/dive.mjs        試し潜り（部屋数、ランタン油、コンボ）
core/save/save.mjs         保存（localStorage `mnemo-manor-v1`）、書き出し・読みこみ
render/timing.mjs          リフレッシュレートの計測
render/sprites.mjs         紋章・宝箱・コウモリの絵
render/flash-view.mjs      閃光・マスク・結果の演出（2D canvas）
ui/answer-pad.mjs          回答ボタンとキーボード
audio.mjs                  効果音（Web Audio で合成）
app.mjs                    画面の切りかえ、フレーム単位の進行
tests/core.test.mjs        node --test games/mnemo-manor/tests/*.test.mjs
```

テストでは、階段法が成功率 約8割に落ち着くこと（仮想プレイヤーで6000回）、段階ごとの出題（妨害物が宝箱や互いに重ならない、偽像が本物と同じ方向に出ない）、段階の上げ下げ、壊れたセーブからの復帰などを確認している。

## M0 で確かめたいこと（DESIGN.md 11章）

- 表示時間の精度：`?debug` で「狙った時間」と「実測」がそろっているか、iPad でフレーム落ちが出ないか
- 階段法が機能するか：何回か潜ると、だいたい8割成功のあたりで表示時間が落ち着くか
- 短い表示が「読めた」ときの気持ちよさがあるか
